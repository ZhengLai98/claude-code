# GitHub Actions build failure 27089522360

## Context

- Workflow: `Release (GitHub Releases)`
- Run: <https://github.com/ZhengLai98/claude-code/actions/runs/27089522360>
- Failed jobs:
  - `build (macos-latest, darwin-arm64, bash)`
  - `build (windows-latest, win32-x64, bash)`
  - `build (ubuntu-latest, linux-x64, bash)`
- Failed step: `Type check`

The GitHub job log download endpoint requires repository admin permission, but
the public Actions job metadata shows every completed platform failed before
`Run tests` and `Build (Vite)`. The same failure is reproducible locally with:

```bash
bun run typecheck
```

## Error

```text
src/services/skillLearning/__tests__/projectContext.test.ts(66,58): error TS2304: Cannot find name 'resolve'.
src/services/skillLearning/__tests__/projectContext.test.ts(109,58): error TS2304: Cannot find name 'resolve'.
```

## Root Cause

`src/services/skillLearning/__tests__/projectContext.test.ts` uses
`resolve(...)` when comparing real project roots, but only imports `join` from
`path`. TypeScript strict checking catches the missing symbol during the release
workflow's `bun run typecheck` step.

Because the release workflow runs type checking before tests and Vite build, the
missing import stops the entire build matrix before artifacts are created.

## Fix

Import `resolve` alongside `join`:

```ts
import { join, resolve } from 'path'
```

The release workflow was also hardened for the next steps after the typecheck
gate:

- Added checkout with `fetch-depth: 0` to the `release` job before running
  `git tag` and `git log`.
- Fixed changelog tag filtering so it excludes the current tag name exactly.
- Generated `ccb-win32-x64.zip.sha256` and fixed the Windows checksum link in
  the release body.
